The Swappable Provider Interface Pattern

To support both platforms simultaneously, we decouple the agentic core from the document storage provider. The core engine only communicates with a unified abstract interface: `IDocumentProvider`.

Google Workspace Adapter

SharePoint Adapter

Writes to Microsoft Office 365 via MS Graph API

Unified Python Adapter Architecture

providers.py

This python snippet represents the codebase architecture we implement within Cloud Run to guarantee hot-swappable providers.

from abc import ABC, abstractmethod

# 1. ABSTRACT PROVIDER INTERFACE
class IDocumentProvider(ABC):
    @abstractmethod
    def create_proposal(self, deal_id: str, context: dict) -> str:
        pass

# 2. MICROSOFT SHAREPOINT/GRAPH ADAPTER
class SharePointProvider(IDocumentProvider):
    def create_proposal(self, deal_id, context):
        # MS Graph call to saturate Word/SOW templates
        return "https://sharepoint.com/sales/Acme_SOW.docx"

# 3. GOOGLE WORKSPACE ADAPTER
class GoogleDriveProvider(IDocumentProvider):
    def create_proposal(self, deal_id, context):
        # Google Docs SDK batch replace templates
        return "https://docs.google.com/document/d/Acme_SOW"

Workload Identity Federation Architecture

When communicating between GCP (Cloud Run) and Azure/Microsoft 365, we **strictly reject** storing hardcoded passwords or API keys inside code or variables. Instead, we implement federated validation.

1

Short-Lived GCP Token

Cloud Run generates a cryptographically signed identity token from Google Cloud's metadata server.

2

Azure Entra Validation

The token is presented to Microsoft Entra ID. Entra matches the signature trust registry with Google's public endpoints.

3

Access Exchange

Entra returns a safe, scoped OAuth access token back to GCP, enabling the agent to execute SharePoint and Teams Graph API writes safely.

Identity Trust Configuration

azure-trust.json
